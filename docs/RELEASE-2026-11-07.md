# Watch — Apple TV build 63

This checkpoint includes the cinematic browsing work, themed and seasonal shelves, daily discovery ordering, exact Christmas episode playback, artwork/title duplication handling, and the subsequent playback and scene-lighting changes.

## Playback and presentation

- The approved full-image Up next card appears in the bottom-right, with a soft gradient, provider badge, episode title, metadata and Next/Exit controls. Countdown stays inside Next; autoplay waits for natural completion.
- Up next is removed from ordinary transport menus. Final episodes return to browsing without an empty completion panel.
- Starting playback omits episode titles that repeat the show title. Explicit sidebar selections return to each section’s root.
- QI lettered series (including Series W and X) participate in chronological queues; named specials remain excluded from guessed ordering.
- Existing provider/source/version marker validation is preserved. Visual/music credits detections are separately identified and never become skip markers.

## Ending analysis

A bounded private preview of the current clear episode’s ending allows the Apple TV to analyse music and picture text before visible playback reaches the credits. It does not prepare the next episode or replace the active stream. Exact-version and duration checks apply; unsupported sources retain provider markers, current-frame detection and the final-ten-second fallback. See [full behaviour and limits](VISUAL-CREDITS.md).

## Scene lighting

Transport controls persist sample window, sampling interval, fade, fixed saturation, optional matching of scene saturation and brightness, neutral-to-white handling and optional ramped look-ahead. Brightness matching is opt-in; black scenes can turn the lamp off, while the default retains starting brightness. Original-state restoration and manual override detection remain active. See [controls and API details](SCENE-LIGHTING-CONTROLS.md).

## Validation and deployment

- Build 63 was built with Xcode and installed on the physical Apple TV.
- QI playback resumed in HD without reported stalls. A device screenshot confirmed the new card’s artwork, title, provider badge, controls and countdown. The user approved its appearance.
- Ending analysis ran on actual QI previews; production diagnostics confirmed detection on Apple TV. Heuristic accuracy varies by programme and credits layout; it is not universal credits recognition.
- Swift checks cover playback timing, completion guards, source/version validation, queue DTOs, credits fallback, music/text evidence, logo duplication, cinematic shelves, colour dominance, calibration, control persistence and look-ahead ramping.
- Pi tests cover paired ownership, preview-duration validation with real ffmpeg, chronological queues, marker handling, lamp brightness/off/recovery/restoration, gateway playback and catalogue artwork.
- Look-ahead scene-to-lamp alignment and all matching-control combinations still need broader physical-device evaluation. Samsung and Home Assistant do not gain the tvOS-only analysis UI from this update.

No account credentials, pairing tokens, private identities, downloaded programmes or private previews are published. The previous `checkpoint-appletv-build-37` tag remains available for rollback; this release uses `checkpoint-appletv-build-63`.
